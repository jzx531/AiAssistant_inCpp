# How To Improve Gomoku AI Strength

当前这版 AI 很弱，核心原因不是单一的 prompt 问题，而是整个决策方式本身不适合五子棋这种强规则、强战术的棋类。

## 1. 根本原因

现在的方案本质上是：

1. 把棋盘状态发给大语言模型
2. 让模型直接输出一个坐标

这种做法有几个先天问题：

1. 大语言模型不是专门的棋类搜索引擎
2. 它擅长语言模式，不擅长稳定、穷举式战术计算
3. 它可能知道五子棋规则，但不代表能稳定算清 2 到 6 步内的强制杀棋
4. 它经常会漏看“马上要输”的局面，或者给出表面合理但战术上错误的点

所以，即使 prompt 写得更长、更像规则说明，它的上限也仍然有限。

## 2. 按收益排序，最值得做的增强方向

### 2.1 先加规则层，不要把所有决策都交给 LLM

最有效的增强不是继续堆 prompt，而是在调用模型之前，先用程序做几层硬规则判断。

建议优先级：

1. 我方有立即成五的点，直接下
2. 对方有立即成五的点，直接堵
3. 我方有活四、冲四、双三这类强杀点，优先下
4. 对方有活四、冲四、双三威胁，优先防
5. 只有当局面没有明显强制手时，才让 LLM 参与决策

这样可以把 AI 从“随便被一眼杀”提升到“至少不会漏掉简单战术”。

这是提升棋力收益最高的一步。

### 2.2 候选点筛选，而不是让模型在全盘乱选

不要让 AI 从整个 16x16 棋盘任意选点。

更合理的方法是先由程序筛出候选点，例如：

1. 只考虑已有棋子曼哈顿距离 1 到 2 格内的空位
2. 只考虑能形成连二、连三、冲四、活四的点
3. 排除明显孤立、远离主战场的空点

然后：

1. 程序在候选点里评分
2. 或把候选点发给模型，让模型只在这些点里选

这样能显著减少低质量落子。

### 2.3 引入静态评估函数

五子棋 AI 的常见做法不是“直接问 LLM 下哪”，而是：

1. 枚举候选点
2. 对每个候选点打分
3. 选分数最高的点

评分可基于棋型：

1. 成五
2. 活四
3. 冲四
4. 活三
5. 眠三
6. 活二

同时分别给：

1. 我方进攻收益
2. 对方威胁防守收益

最后综合成一个分数。

这是非常经典而且对五子棋非常有效的方法。

### 2.4 用搜索，不只看一步

如果只下一步贪心，AI 很容易“看不到下一回合就要死”。

更强的方法是：

1. Minimax
2. Alpha-Beta 剪枝
3. 迭代加深
4. 只对候选点做搜索

即使只搜索 2 到 4 层，在五子棋里就已经能比现在的纯 LLM 下法强很多。

对当前项目来说，最现实的路线是：

1. 候选点生成
2. 静态评分
3. 小深度 Alpha-Beta

这会比任何 prompt 调整都更有效。

### 2.5 LLM 更适合“辅助排序”，不适合“独立决策”

如果还想保留 Ollama，可以把它的位置降级为辅助模块。

更合理的使用方式：

1. 程序先筛出前 5 到 10 个候选点
2. 程序先做基础评分
3. 再把这些候选点和局面摘要给模型
4. 让模型在有限候选里排序或做最终选择

而不是让模型直接面对完整棋盘后自由输出一个坐标。

这样模型更像“顾问”，程序才是“裁判和执行者”。

## 3. 如果只改很少代码，优先做什么

如果希望尽量少改代码，但又显著增强 AI，建议按这个顺序做：

1. 增加“立即获胜/立即防守”硬规则
2. 增加候选点范围限制
3. 增加基础棋型评分
4. 仅在候选点中让 Ollama 排序
5. 再考虑小深度搜索

只做前 1 到 3 项，棋力通常就会比现在提升非常明显。

## 4. Prompt 还能怎么改，但收益有限

Prompt 还能继续优化，但作用主要是“减少胡乱落子”，不是“真正学会算棋”。

可以补充的方向：

1. 明确要求先检查双方是否有立即成五
2. 明确要求优先防守对手活四/冲四
3. 明确要求只在给定候选点中选择
4. 让模型输出“为什么选这个点”，程序再只取坐标

但是要注意：

1. prompt 更长不一定更强
2. 更长的 prompt 会更慢
3. 更长的 prompt 仍然不能替代搜索和规则判断

## 5. 模型选择也会影响强度

如果继续用 Ollama，本地模型也会影响表现。

一般来说：

1. 更大的模型，理解描述能力更强
2. 但不代表棋力会线性提升
3. 纯靠通用聊天模型下五子棋，上限仍然不高

可以尝试：

1. 更稳定的指令模型
2. 更擅长结构化输出的模型
3. 更低温度、减少随机性

但这些都属于锦上添花，不是根本解决方案。

## 6. 最推荐的最终方向

如果目标是“这个 Gomoku AI 真的能下得像样”，最推荐的结构是：

1. 程序做棋规判断
2. 程序做候选点生成
3. 程序做棋型评分
4. 程序做小深度搜索
5. LLM 只做补充排序或解释

也可以完全不要 LLM，直接做传统五子棋 AI。对这种游戏来说，这通常更强、更稳、更快。

## 7. 一句话结论

真正能显著增强它棋力的，不是把 prompt 再写长，而是把“立即战术判断 + 候选点筛选 + 棋型评分 + 小深度搜索”加到程序里，让 LLM 从主决策者变成辅助模块。
